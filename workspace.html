PRD — Business & Planning

Approved
Phase 1 · Dibuat oleh Business Analyst Agent · Terakhir diupdate 1 Sep 2026 14:32

Ringkasan

Dokumen ini mendefinisikan apa yang akan dibangun, untuk siapa, dan mengapa.

Problem Statement

Proses distribusi PAD saat ini masih manual dan terpisah antar unit, menyebabkan data tidak akurat, pelaporan lambat, dan kontrol keuangan lemah.

Product Vision

Membangun platform ERP terintegrasi untuk mengelola distribusi PAD secara akurat, transparan, dan real-time.

Target Users

Admin, Finance, Accounting, Sales, Warehouse, Procurement, Production.

Scope (In)

Manajemen master data, sales order, distribusi, persediaan, pembelian, keuangan, akuntansi, pajak, laporan, produksi.

Scope (Out)

Human Resources, Payroll, CRM eksternal di luar integrasi yang direncanakan.

Success Metrics

  • 100% data transaksi terintegrasi
  • Laporan keuangan real-time
  • Pengurangan error input > 80%

User Stories & Acceptance Criteria

Kumpulan use case dan kebutuhan operasional pengguna.

US-01: Master Data Management

Sebagai Admin, saya ingin membuat dan mengelola data master customer & vendor agar transaksi dapat terpetakan dengan akurat.

US-02: Sales Order Automation

Sebagai Sales Officer, saya ingin membuat pesanan penjualan secara online dan langsung meneruskannya ke gudang.

System Architecture Overview

Arsitektur berlapis (N-Tier) dengan Microservices, event-driven message queue, dan database cluster.

Presentation & Client Layer
Web Application Responsive Next.js & Tailwind UI Next.js 14 · SSR
Mobile Companion Warehouse & Delivery Scanner React Native / PWA
API Gateway & Auth
Zenith API Gateway Rate Limiting, JWT Verification, RBAC Kong / Envoy Proxy
Domain Microservices
Order & Sales Service Order lifecycle & workflow Go Gin / gRPC
Inventory Service Stock tracking & barcode ledger Go / Node.js
Finance & Ledger General ledger, invoice & tax Python FastAPI
Storage & Telemetry
Primary Database PostgreSQL 16 Cluster + Timescale PostgreSQL
In-Memory Cache Session store & Hot product caching Redis v7
Message Queue Async events & PDF invoice export RabbitMQ

Technical Specification & Security Protocol

Standarisasi RESTful envelope, model autentikasi JWT + Role Based Access Control (RBAC).

🔐 Authentication & RBAC

Setiap request wajib menyertakan Header Authorization: Bearer <JWT>. Token memiliki TTL 15 menit dengan Refresh Token rotasi di cookie HttpOnly.

📦 API Response Standard

Format seragam: { "success": true, "data": {...}, "meta": {...}, "timestamp": 1788316800 } untuk semua endpoint JSON.

⚡ Caching Strategy

Cache-Aside pattern di Redis dengan invalidasi otomatis saat terjadi mutasi event (Write-Through pada inventory ledger).
